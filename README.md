# Linux Networking Practical Tasks

## Overview

This repository contains the completed practical tasks for Linux networking and cloud networking.

The practical work covers Linux IP investigation, IPv4 address analysis, dynamic IP addressing, AWS EC2 Linux server configuration, and cloud network troubleshooting.

## Tasks Completed

### Task 1 — Linux IP Investigation

- Identified the Linux system's IP address.
- Identified the active network interface.
- Found the default gateway.
- Checked DNS information.
- Displayed the complete network configuration.
- Documented the commands and their outputs.

📄 [View Task 1](task%201.pdf)

### Task 2 — IPv4 Address Analysis

- Identified the IPv4 address assigned to the Linux machine.
- Separated the IPv4 address into four octets.
- Identified the value of each octet.
- Determined whether the IP address was private or public.
- Investigated network and host information.
- Compared the Linux machine's IP address with two other accessible devices/systems.

📄 [View Task 2](task%202.pdf)

---

### Task 3 — Dynamic IP Investigation

- Recorded the IP address before network reconnection.
- Checked network connection status.
- Disconnected and reconnected the network where applicable.
- Checked the IP address after reconnection.
- Compared the old and new IP addresses.
- Documented whether the IP address changed.

📄 [View Task 3](task%203.pdf)

---

### Task 4 — Cloud Linux Server & IP

- Created an AWS EC2 Linux instance.
- Connected to the instance using SSH.
- Identified the private IP address from inside Linux.
- Identified the public IP address.
- Compared the IP information shown inside Linux with the AWS cloud console.
- Documented the commands and results.

📄 [View Task 4](task%204.pdf)

---

### Task 5 — Cloud Network Troubleshooting

- Checked the cloud server IP address.
- Checked the network interface.
- Checked the default route.
- Tested network connectivity.
- Checked running services.
- Checked listening ports.
- Checked firewall and security rules.
- Identified and fixed the networking/service issue.
- Verified that the service was working successfully.
